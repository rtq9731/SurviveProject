# 번역 체계

이 문서 하나만 읽고 다음 문자열 이관을 이어갈 수 있어야 한다.

---

## 0. 왜 자체 CSV 층인가

기성품을 먼저 조사했다.

- **Unity Localization 공식 패키지** — 개념(String Table Collection = 카테고리, Entry Name = 키)은
  우리 요구와 잘 맞는다. 그런데 **Addressables가 하드 의존**으로 딸려 오고 이 프로젝트에는
  Addressables가 전혀 없다. 더 큰 문제는, 그 패키지의 진짜 가치인
  "프리팹의 TMP 컴포넌트에 `LocalizeStringEvent`를 붙이는" 워크플로를 **이 프로젝트가 쓸 수 없다**는 것이다 —
  UI를 전부 코드에서 `GameObject`로 조립하기 때문에 붙일 프리팹이 없다.
- **I2 Localization** — 유지보수가 멎은 것으로 보여 제외.
- **실측 규모** — 코드 안 한글 문자열 약 214개(주석·인스펙터 속성·테스트 제외),
  데이터 에셋 텍스트 칸 **147개**. 합쳐 약 360개. 얇은 층 하나로 충분한 크기다.

  데이터 에셋 147칸의 내역(2026-08-06 실측, `Assets/08.Data`의 ScriptableObject 107개):
  `displayName` 71 / `description` 23 / `hint` 7 / `codexDescription` 5 /
  `title` 1 / `displayText` 6 / 대사(`speaker`+`text`) 34.
  앞선 라운드의 개략 실측(101칸)은 `displayName`·`description`·`hint`만 센 것이었다 —
  생물 도감 본문, 챕터 제목, 목표 문구, 연구·프롤로그 대사가 빠져 있었다.

그래서 **CSV 한 장 + 동기 조회 API + EditMode 게이트**로 갔다.
나중에 Unity Localization으로 갈아탈 수 있게 열 구조를 그쪽과 맞춰 두었다(3절).

## 1. 파일과 형식

**위치**: `SurviveProject/Assets/Resources/Localization/strings.csv`

`Resources` 아래에 둔 이유는 셋을 한꺼번에 만족해야 하기 때문이다 —
게임이 뜨는 **첫 프레임 전에**, **씬과 무관하게**, **동기로** 읽혀야 한다.
Addressables 없이 그것이 되는 것은 Resources뿐이다.
읽는 자리는 `Assets/02.Scripts/Localization/LocalizationBootstrap.cs` 하나뿐이므로,
나중에 갈아탈 때 고칠 파일도 그 하나다.

**CSV가 진실의 원천이다.** 에디터 창에서 편집해 내보내는 방향이 아니다.
사람이 이 파일을 고치면 그것이 곧 게임에 반영된다. git diff가 되고,
번역가에게 그대로 보낼 수 있다.

```csv
Category,Key,ko,en
UI,craft_empty,아직 아는 제작법이 없다,
UI,no_ingredients,재료 없음,No materials
Item,mushroom_wood.name,버섯 목재,
```

- 첫 줄이 헤더다. 첫 칸은 반드시 `Category`, 둘째 칸은 반드시 `Key`, 그 뒤가 로케일 열이다.
- **`ko` 칸은 절대 비우지 않는다.** 비면 EditMode 게이트가 실패한다.
- 다른 로케일 칸은 비워도 된다. 비면 `ko`로 폴백한다.
  (**빈 칸은 표에 담지 않는다** — 담으면 화면이 비고 폴백이 돌 자리가 사라진다.)

### 파서 규칙 (RFC 4180 + 두 가지)

`Assets/02.Scripts/Domain/Localization/Csv.cs`. 직접 썼다 — 필요한 것은 아래뿐이다.

| 경우 | 쓰는 법 |
|---|---|
| 값에 쉼표 | `UI,k,"재료가 없다, 아직은"` — **한국어에 쉼표는 흔하다** |
| 값에 따옴표 | `UI,k,"그는 ""안 된다""고 했다"` |
| 값에 줄바꿈 | 따옴표로 감싸면 그 안의 줄바꿈은 값의 일부다 |
| 앞뒤 공백 보존 | 따옴표로 감싼다. 감싸지 않아도 파서는 값을 trim하지 않는다 |
| CRLF / LF | 섞여도 된다 |
| UTF-8 BOM | 앞머리 BOM은 무시한다 (엑셀이 저장하면 붙는다) |

RFC에서 벗어난 두 가지 — 둘 다 사람이 표를 구역별로 나눠 읽으라고 허용했다.

- **빈 줄**은 레코드로 세지 않는다.
- **`#`로 시작하는 줄**은 주석이다. (Unity Localization으로 내보낼 때는 이 줄들이 사라진다.)

값 안의 `#`는 영향이 없다. 줄 **첫 글자**만 본다.

## 2. 조회 API

`Assets/02.Scripts/Domain/Localization/Loc.cs`. **전부 동기다.**
제작 화면(`CraftingUI`)은 열려 있는 동안 **매 프레임** 목록을 다시 그린다 —
async가 하나라도 끼면 그 자리는 한 프레임 비었다가 채워진다.

```csharp
using Survive.Localization;

Loc.T("UI", "craft_empty")            // 현재 로케일
Loc.T("Item", "mushroom_wood.name")
Loc.F("UI", "battery_percent", 62)    // 서식 인자 (1~3개 + params)
```

### 폴백 사슬 (세 단)

1. 현재 로케일 표
2. 기본 로케일(`ko`) 표
3. **키 자체**

**어느 단계에서도 빈 문자열이나 예외를 내지 않는다.**
번역이 빠졌다고 화면이 비면 무엇이 빠졌는지조차 보이지 않는다.
키가 그대로 뜨면 적어도 어디를 고쳐야 하는지가 보인다.
`Loc.F`는 서식이 번역과 어긋나 `FormatException`이 나도 번역문을 그대로 낸다.

### 성능 계약

- 조회는 **사전 한 번 뒤짐**이다. `Loc`이 현재 로케일 표와 기본 로케일 표의
  참조를 직접 붙들고 있어, 로케일 이름으로 사전을 한 번 더 뒤지지 않는다.
- 이름표는 `LocKey` 구조체다(`Category` + `Key` 두 참조).
  `category + "/" + key`로 이어 붙이면 매 프레임 문자열이 새로 생긴다.
- 의사 번역도 로케일을 바꾸는 순간 표를 통째로 한 번 만들어 두고,
  그 뒤로는 다른 로케일과 똑같은 사전 조회다.

### 로케일 전환

```csharp
Loc.SetLocale("en");                        // 표에 없는 이름을 줘도 막지 않는다 (전부 ko로 폴백)
Loc.SetLocale(StringCatalog.PseudoLocale);  // "pseudo"
Loc.AvailableLocales                        // 표의 로케일 + pseudo
Loc.LocaleChanged += ...                    // 로케일이 바뀌었거나 표를 새로 읽었다
```

**`LocaleChanged`를 누가 들어야 하는가.**

- **매 프레임 다시 그리는 화면**은 구독할 필요가 없다. 저절로 따라온다
  (`CraftingUI.Update` → `RefreshList`).
- **한 번 쓰고 마는 글자**는 반드시 들어야 한다. 버튼 캡션, `Awake`에서 세운 안내문 등.
  창을 닫았다 열면 바뀌어 있어서 사람 눈으로는 통과한 것처럼 보인다 —
  E2E(`E2ELocaleSwitch`)가 **창을 연 채로** 바꿔서 이 차이를 잡는다.

예: `CraftingUI.ApplyStaticText()`, `BuildMenuUI`의 `Loc.LocaleChanged += Refresh`.

### Category

`^[A-Z][A-Za-z0-9]*$` (EditMode 테스트가 강제한다).

나중에 Unity Localization으로 갈아탈 때 **String Table Collection 이름**이 되므로
파일 이름으로 쓸 수 있어야 한다.

### Key

`^[a-z0-9]+([._][a-z0-9]+)*$` (EditMode 테스트가 강제한다). 소문자 스네이크, 점으로 갈래.

- `UI` 아래는 **손으로 짓는다**: `craft_empty`, `no_ingredients`, `craft_max_button`.
  화면·역할이 보이는 이름으로. 문장을 그대로 키로 쓰지 마라(번역이 바뀌면 키가 흔들린다).
- **데이터 에셋은 `{id}.{필드}`로 자동 생성한다**.
  `ItemDataSO.id == "mushroom_wood"` → `Item/mushroom_wood.name`, `Item/mushroom_wood.desc`.
  접미어 전체 목록은 위 표와 `DataText.Suffix`.

`id` 필드가 없는 세 종류는 다른 데서 키 조각을 가져온다(`DataText.IdOf`).

| 에셋 | 어디서 | 예 |
|---|---|---|
| `HarvestNodeSO` | 에셋 파일 이름 | `LooseScrap.asset` → `Harvest/loose_scrap.name` |
| `PlantNodeSO` | 에셋 파일 이름 | `AshFern.asset` → `Plant/ash_fern.name` |
| `SceneReferenceSO` | `sceneName` (Build Settings 이름) | `MainScene` → `Scene/main_scene.name` |

파스칼케이스를 소문자 스네이크로 바꾸는 규칙은 `DataText.Slug`이고 EditMode가 예시로 못 박는다.
**에셋 이름을 바꾸면 키가 바뀐다** — 그 셋은 이름을 바꾸기 전에 표의 키도 같이 고쳐라.

대소문자는 **구별한다**. `craft_empty`와 `Craft_Empty`는 다른 줄이다.
앞뒤 공백은 떼어 낸다.

## 4. 의사 번역 (pseudo)

`Loc.SetLocale("pseudo")` → 모든 문자열이 `[!! 최대~ !!]` 꼴로 나온다.

목적 둘.

1. **번역 밖에 있는 글자가 드러난다.** 화면에 부풀지 않은 한국어가 보이면
   그 자리는 `Loc`을 거치지 않는 하드코딩이다.
   214곳을 옮기는 동안 "다 옮겼는가"를 눈으로 판정할 수 있는 유일한 방법이다.
2. **길어졌을 때 판이 깨지는지 미리 본다.** 영어·독일어는 한국어보다 길다.
   통례대로 35% 늘린다.

`pseudo`는 CSV에 열로 두지 않는다(두면 진실이 둘이 된다 — 표에 `pseudo` 열이 있으면
파서가 문제로 적는다). 기본 로케일(`ko`) 값을 바탕으로 만들어 낸다.
표에 아예 없는 키는 부풀리지 않고 키를 그대로 낸다 —
"부풀지 않은 것이 하드코딩"이라는 신호를 흐리지 않기 위해서다.

### 글자를 고른 근거 (중요)

본문 글꼴은 `Assets/07.Fonts/TMP/ChosunGu SDF.asset`이고 **아틀라스가 Dynamic**이다.
즉 원본 `ChosunGu.TTF`에 있는 글자만 찍히고, 없으면 두부(□)가 뜬다.

**확인 방법** — `uloop execute-dynamic-code`로 아래를 돌린다.

```csharp
var font = AssetDatabase.LoadAssetAtPath<TMP_FontAsset>("Assets/07.Fonts/TMP/ChosunGu SDF.asset");
// 세 번째 인자 tryAddCharacter=true 이면 원본 TTF까지 뒤져 판정한다
bool ok = font.HasCharacter('~', false, true);
```

실측 결과(2026-08-06):

| 있다 | 없다 (□로 뜬다) |
|---|---|
| `[ ] ! ~ < > ( ) * # + = - _ / \| : . , · … ¡ ¿ ß Ł` | `— (em dash)` `− (U+2212)` `« » ‹ ›` `⟦ ⟧` `À É Ü Ž Đ` |
| `《 》 【 】 〔 〕 （ ）` `→ ← ↑ ↓ ★ ☆ ● ○ ■ ▲ ▼` | |

**악센트 라틴 문자를 쓸 수 없다** — 흔한 의사 번역 관례가 여기서는 통하지 않는다.
그래서 ASCII `[ ] ! ~`만 쓴다.
EditMode 테스트(`의사_번역은_글꼴에_있는_글자만_쓴다`)가 접두·접미가 ASCII임을 못 박고,
`표의_값에_글꼴에_없는_글자가_없다`가 CSV 값에 위 "없다" 목록이 섞이는 것을 막는다.

> 화면에 나가는 문자열에 **em dash(—)를 쓰지 마라.** 코드 주석과 이 문서에는 써도 된다.

### 누락 키 게이트 (둘이다)

**① 코드 쪽.** `Assets/02.Scripts` 아래 모든 `.cs`를 긁어(`LocSourceScanner`)
`Loc.T("Cat","key")` / `Loc.F("Cat","key",…)`를 뽑고 CSV와 대조한다.

- **코드가 부르는 키가 표에 없으면 실패한다.** 실패 메시지에 없는 키를 그대로 적어 준다.
- 주석 안의 예시(`/// Loc.T("UI","예시")`)는 세지 않는다 — 주석을 먼저 지운다.
- **리터럴 인자만 검사할 수 있다.** `Loc.T("Item", id + ".name")`처럼 변수로 만든 키는
  판정 불가이고, 개수만 세어 콘솔에 남긴다.
- 반대 방향(표에 있는데 코드가 안 부르는 키)은 **경고로만** 남긴다.

**② 에셋 쪽** (`DataTextGateTests`). 위 사각지대를 메운다. 소스를 긁는 대신
`Assets/08.Data`의 에셋을 **실제로 열어** 필요한 키를 계산하고 표와 대조한다.
아이템을 하나 새로 만들고 번역 키를 안 만들면 다음 EditMode에서 즉시 빨개진다.
자세한 것은 8절.

### 표 건전성

`StringCatalog.Problems`가 비어 있어야 한다.
중복 `(Category,Key)`, 헤더와 칸 수가 다른 줄, 헤더 첫 두 칸 이름,
헤더에 `pseudo` 열, 빈 `ko` 칸.

### E2E

둘 다 **아무것도 다시 열지 않고** 로케일을 바꾼 뒤, 화면에 실제로 서 있는
글자 오브젝트를 직접 읽는다. 창을 닫았다 열면 언제나 통과하기 때문이다.

| 시나리오 | 무엇을 본다 |
|---|---|
| `E2ELocaleSwitch.FullRun()` | 제작 창을 연 채로 `ko → pseudo → en → ko`. 코드 문자열(버튼 캡션) |
| `E2EDataTextLocale.FullRun()` | 줍기 프롬프트를 겨눈 채로 `ko → en → pseudo`, 그리고 **표를 통째로 치웠을 때** 에셋 원문으로 돌아가는지. 데이터 에셋 문자열 |

```
npx --yes uloop-cli@2.2.0 control-play-mode --action play
# execute-dynamic-code: E2ERunner.Run("로케일 전환", E2ELocaleSwitch.FullRun());
# execute-dynamic-code: E2ERunner.Run("데이터 에셋 번역", E2EDataTextLocale.FullRun());
```

줍기 프롬프트를 고른 이유: `PlayerInteractor`가 매 프레임 다시 묻고 달라졌을 때만
HUD로 밀어 넣는 자리라, 화면을 건드리지 않고도 글자가 바뀌는 것을 볼 수 있다.

## 6. 새 언어를 더하려면

1. `strings.csv` 헤더 끝에 로케일 코드를 더한다: `Category,Key,ko,en,ja`
2. 그 열을 채운다. 비워 두면 `ko`로 폴백한다. **줄 수는 건드리지 않는다.**
3. `Loc.SetLocale("ja")`.
4. 글꼴을 확인한다. ChosunGu에 그 언어 글자가 없으면 전부 두부(□)가 된다 —
   4절의 확인 방법으로 먼저 재고, 없으면 그 로케일용 폰트 에셋과 fallback을 따로 붙여야 한다.
   **이것은 아직 안 되어 있다.**

로케일을 고르는 **화면**은 아직 없다. 지금은 코드/E2E에서 `Loc.SetLocale`을 부른다.

## 8. 데이터 에셋

### 왜 필드를 지우지 않았는가

`ItemDataSO.displayName`은 **그대로 남아 있다.** 표는 옮겨 담는 그릇이 아니라
**덮어쓰는 층**이다. 셋을 한꺼번에 얻는다.

1. 이관 도중 아무것도 깨지지 않는다 (키가 없으면 지금까지와 똑같이 돈다).
2. 표가 없거나 망가져도 게임은 한국어로 돌아간다.
3. 인스펙터에서 그 에셋이 무엇인지 여전히 읽힌다.

### 조회 경로 — `DataText`

`Assets/02.Scripts/Domain/Localization/DataText.cs`. **모든 읽기가 여기를 지난다.**

```csharp
using Survive.Localization;

DataText.Name(item)          // Item/{id}.name 이 표에 있으면 그것, 없으면 item.displayName
DataText.Desc(item)          // Item/{id}.desc
DataText.Hint(blueprint)     // Blueprint/{id}.hint
DataText.Line(discovery)     // Discovery/{id}.line.text
DataText.Line(sequence, 0)   // Sequence/{id}.line1.text
```

- 폴백은 **키가 아니라 에셋 원문**이다. `Loc.T`의 마지막 단(키를 그대로 내주기)과 다르다 —
  여기서는 원문이 언제나 키보다 나은 답이다. 그래서 `Loc.TryT`를 쓴다.
- **어느 경로에서도 빈 글자를 내지 않는다.** 원문의 앞뒤 공백은 뗀다
  (인스펙터의 `TextArea`에 줄바꿈이 딸려 들어가는 일이 흔한데,
  표를 거친 값에는 그런 것이 안 붙으므로 두 경로의 답이 달라지면 안 된다).
- `id`가 비어 있으면 키를 못 지으므로 표를 뒤지지 않고 곧장 원문을 낸다.

**한 문으로 모으는 이유.** 한 군데라도 SO를 직접 읽으면 그 화면만 번역이 안 되고,
그 구멍은 그 화면을 그 로케일로 열어 보기 전까지 아무 신호도 내지 않는다.
`DataTextGateTests.접근자를_우회해_SO를_직접_읽는_곳이_없다`가 `Assets/02.Scripts` 전체를
정적으로 훑어 `.displayName` / `.description` / `.hint` / `.codexDescription` /
`.displayText`를 **읽는** 자리를 잡아낸다(대입은 세지 않는다).

### 초안 생성 도구

메뉴 **`Tools/Survive/번역/데이터 에셋 초안 갱신`**
(미리보기: `… 초안 미리보기 (쓰지 않는다)`).
`Assets/02.Scripts/Editor/LocDataDraftTool.cs` → 규칙은 `Domain/Localization/DataTextDraft.cs`.

CSV 안에 **경계선**이 있다.

```
# ======== 여기부터 데이터 에셋 자동 생성 구역 (손으로 줄을 더하지 마라) ========
```

- **위쪽은 글자 하나 건드리지 않는다.** 손으로 짓는 `UI`·`Prompt` 줄들의 자리다.
- **아래쪽은 다시 쓴다.** 다만 **다시 쓰는 것은 순서와 주석뿐**이고,
  이미 있던 줄의 칸 내용은 읽은 그대로 되돌려 놓는다.
  번역가가 채운 `en` 칸을 도구가 지우면 그 도구는 두 번 다시 쓰이지 않는다.
- 카테고리·키로 **정렬**해 쓴다. 끝에 덧붙이기만 하면 몇 번 돌린 뒤 순서가
  에셋을 만든 순서가 되어 git diff를 읽을 수 없다.
- **표에는 있는데 어느 에셋도 만들지 않는 키는 지우지 않는다.** 콘솔에 적기만 한다.
- **에셋의 한국어가 바뀌어도 표를 덮지 않는다.** 어긋난 것을 콘솔에 적기만 한다 —
  사람이 고친 번역일 수도 있으므로 어느 쪽이 맞는지는 사람이 정한다.
- 표의 헤더가 망가져 있으면 **아무것도 쓰지 않고** 중단한다.

### 번역가에게 맥락을 남기는 법

CSV 파서는 줄 첫 글자가 `#`이면 주석으로 넘긴다(1절). 그 성질을 그대로 쓴다.

- **카테고리 머리 주석** — 그 구역이 무엇인지. `DataTextCatalog.BlockNote`가 짓는다.
- **줄 바로 위 주석** — 그 한 줄에만 해당하는 맥락. `DataTextEntry.Note`.

열을 하나 더하지 않은 이유: 헤더의 `Key` 뒤는 전부 로케일 열이라
`note` 열을 넣으면 파서가 그것을 로케일로 오해한다. 진실이 둘이 되는 것보다
이미 있는 주석 기능을 쓰는 편이 안전하다.

지금 남기고 있는 맥락:

```
# ---- Discovery ----
#   재료를 처음 손에 넣었을 때 AI가 하는 말(.line.text).
#   화자는 우주복 AI, 기계다. 세 문장 고정:
#     [관찰된 성질] 분석... [용도 판정, "~것으로 보입니다"]. [해금 정형구].
#     아이템 이름을 되뇌지 않는다. 감탄/추측/이모지/물음 금지. ...
#   현장 발견의 마지막 문장: "해당 물질을 사용한 제작법이 있습니다."
Discovery,disc_scrap.line.speaker,우주복 AI,
#   재료를 처음 쥐었을 때의 대사. 대상 아이템: 스크랩 (scrap)
Discovery,disc_scrap.line.text,외계 금속물체 분석... ...,
```

문체 규격의 **원본은 `DiscoverySO`의 문서 주석**이고, 표에 적힌 것은 그 요약이다.
규격이 바뀌면 두 곳을 같이 고친다(`DataTextCatalog.AiVoiceNote`).
연구(`ResearchEntrySO`)는 마지막 정형구만 다르다 —
주운 것과 밝혀낸 것은 같은 문장으로 말할 수 없다.

### 글꼴에 없는 글자

에셋 네 곳에 줄표(—)가 들어 있다. ChosunGu에 없어 **화면에서 두부(□)로 뜬다.**

| 에셋 | 필드 |
|---|---|
| `08.Data/Chapters/Chapter1_FloatingIsland` | `title` |
| `08.Data/Items/잠항구` | `description` |
| `08.Data/Scenes/Scene_MainScene` | `displayName` |
| `08.Data/Scenes/Scene_StartScene` | `displayName` |

에셋의 한국어 원문은 이번 라운드에서 손대지 않기로 했으므로 **표가 바로잡는다.**
`FontSafe.Sanitize`가 `—`를 가운뎃점(`·`)으로 바꿔 `ko` 칸에 넣고,
왜 원문과 다른지를 그 줄 위 주석에 적는다. 표는 덮어쓰는 층이므로
이런 고침에 딱 맞는 자리다. **에셋 쪽을 고치는 편이 더 낫고**, 고치면
그때 표의 값과 원문이 저절로 맞아떨어진다(도구가 어긋남을 알리지 않게 된다).

대치할 짝이 없는 글자(악센트 라틴 문자 등)는 **그대로 남긴다.**
아무 글자나 밀어 넣는 것보다 게이트가 실패해 사람이 판단하는 편이 낫다.

### 새 아이템(또는 어떤 데이터 에셋이든)을 추가할 때

1. 에셋을 만들고 `id`와 한국어를 여느 때처럼 적는다.
2. 메뉴 `Tools/Survive/번역/데이터 에셋 초안 갱신`을 돌린다.
3. 콘솔에 "새로 넣은 키"가 뜬다. `strings.csv`의 diff를 확인한다.
4. EditMode를 돌린다. **2번을 건너뛰면 `DataTextGateTests`가 실패하고
   빠진 키와 에셋 경로를 그대로 적어 준다.**
5. 화면에서 그 이름을 읽는 코드는 **반드시 `DataText`를 거쳐야 한다.**
   직접 읽으면 정적 검사가 잡는다.

에셋을 **지웠을** 때는 도구가 "어느 에셋도 만들지 않는 키"로 알려 준다.
표에서 지울지 말지는 사람이 정한다(번역이 아까울 수 있다).

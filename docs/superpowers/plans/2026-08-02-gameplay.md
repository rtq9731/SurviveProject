# 계획 2: 게임플레이 시스템

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans 또는 subagent-driven-development.

**Goal:** 계획 1의 기반 위에 채집·제작·생물·환경·목표·HUD를 올려 "자원을 모아 만들고, 생물을 상대하고, 목표를 따라가는" 상태를 만든다. Feel·DOTween·Cinemachine을 실제로 작동시킨다.

**Architecture:** 계획 1의 두 계층을 유지한다. 순수 로직·데이터 SO는 `Domain/`, MonoBehaviour는 `Assembly-CSharp`.

**선행:** 계획 1 완료 (커밋 `9954fea`)

---

## Global Constraints (계획 1에서 확정 + 실행하며 배운 것)

- `Domain/`에는 MonoBehaviour·Feel·DOTween·InputSystem을 넣지 않는다.
- `Domain/` 밖에서는 Feel `MMF_Player`·DOTween·Cinemachine을 적극적으로 쓴다 (설계 4.15).
- 아이템 id는 소문자 스네이크 케이스 `string`.
- 사용자에게 보이는 문자열은 한국어. 한글 `Text`는 `ChosunGu` 폰트.
- **씬 저장은 `EditorSceneManager.MarkSceneDirty(scene)` 후 `SaveScene(scene)`.** `SaveOpenScenes()`는 디스크에 쓰지 않는 경우가 있다.
- **동적 코드에서 게임 타입을 `using`으로 직접 참조한다.** `System.Type.GetType`은 보안 정책(`dynamicCodeSecurityLevel: 1`)에 막힌다.
- **`SerializedObject`로 새 컴포넌트 필드를 설정하면 저장되지 않는 경우가 있다.** 리플렉션으로 직접 대입 후 `EditorUtility.SetDirty`가 확실하다.
- 검증 헬퍼: `bash <scratchpad>/uc.sh test`
- `uloop simulate-keyboard`: `--action Press|KeyDown|KeyUp`, `--duration`은 **초**.
- 자동 입력 검증에는 Input System의 `Play Mode Input Behavior`가 `AllDeviceInputAlwaysGoesToGameView`여야 한다.
